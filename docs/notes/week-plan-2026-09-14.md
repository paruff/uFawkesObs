## Why this sequence (the top-0.1% lens)

A principal SRE/observability engineer looking at this backlog would not
pick tasks by P-tier alone — they'd resequence around **trust and data
integrity first, new capability second**, because:

1. **Silent failures are the one thing this repo has already been burned
   by** (AGENTS.md §4, `tests/`: the 2026-08-18 Pushgateway incident — a
   swallowed exception hid two real bugs). [#334](https://github.com/paruff/uFawkesObs/issues/334)
   — `Prometheus /-/reload` returning 200 without applying config — is
   exactly that failure class, sitting in P3 today. It stays low-priority
   only until someone reasons about it from "what does this undermine" —
   it directly contradicts Core Principle 3 in VISION.md ("Hot
   Configuration Reloading"). A reload path that lies about success is
   worse than no hot-reload at all, because it's invisible until an
   incident.
2. **A metrics platform whose own telemetry is unreliable has no right to
   exist.** [#324](https://github.com/paruff/uFawkesObs/issues/324) —
   dropped DORA deployment events unpairing rollback recovery — corrupts
   the exact metric (Rework Rate / MTTR) this product's DORA
   differentiator depends on. Fix data integrity before chasing feature
   work.
3. **Finish the one thing that's already blocking a milestone gate before
   opening new ones.** LB-04 (rollback drill) is the single remaining
   hard blocker on H2 exit criteria. Everything else this week is
   schedulable around it, but LB-04 goes first and gets two full days
   because a rollback drill that's rushed isn't a validated rollback
   drill.
4. **Security hardening is not urgent until reliability is proven** — a
   perfectly-sandboxed agent operating on a stack with silent failures
   and dropped events is still shipping a broken product safely. #357
   comes after the reliability fixes, not before.
5. **Audits close, they don't linger.** LB-02 (ports) has been sitting at
   "partially audited" — a 0.1% engineer doesn't let a security-adjacent
   gate stay half-done across multiple sprints. It gets a hard stop this
   week: fully closed or explicitly re-scoped with a new acceptance
   criterion.

## Wednesday 2026-09-16

### 🎯 Primary Goal

Fix the silent-failure class in [#334](https://github.com/paruff/uFawkesObs/issues/334) — `Prometheus /-/reload` must fail loudly when it fails.

### 📋 Target Issues

- [ ] **#334:** Reload endpoint returns 200 without applying config —
  *Acceptance:* a regression test that pushes an invalid scrape config,
  hits `/-/reload`, and asserts the failure is surfaced (non-zero exit
  from the reload script, or an alert/log line) rather than swallowed.

### ⚡ Execution Protocol

1. **RED:** Write a test that reproduces the lie — broken config,
   `/-/reload` returns 200, but `/api/v1/status/config` never changes.
2. **GREEN:** Make the reload wrapper compare pre/post config state (or
   check Prometheus's own reload-error log line) and exit non-zero / ping
   Alertmanager on mismatch, per AGENTS.md's "never swallow an exception
   without logging what broke" rule.
3. **REFACTOR:** Add this failure mode explicitly to
   `docs/KNOWN_LIMITATIONS.md` as closed, and to
   `docs/CHANGE_IMPACT_MAP.md` if the reload script's blast radius changed.
4. Verification: `make test-unit`; confirm the new test fails on the old
   script and passes on the fixed one (run against a git stash of the fix
   to prove it's a real regression test, not a tautology).
